ScalaTion

SCALAble SimulaTION — a Scala-based system for Simulation, Optimization and Analytics

Quick start · Packages · Scaladoc · Papers · License

Welcome to ScalaTion, the Scala-based system for Simulation, Optimization and Analytics.

This system, coded in Scala, supports multi-paradigm simulation modeling including tableau, event, process, dynamics, dynamics_pde, activity and state oriented models.

Scala is a modern object-oriented, functional programming language that is well-suited for developing simulation engines. It is in the Java family of languages and can call Java code. The inclusion of advanced and functional programming capabilities makes the code much more concise than Java. ScalaTion also supports optimization and analytics, as they nowadays go hand-in-hand with simulation modeling. Some of the algorithms come in both sequential and parallel versions.

ScalaTion 2.0 defines multiple .par subpackages that contain parallel versions of sequential algorithms. Future directions include completing the scala3d and physics packages.

Quick start

1. Clone the repository

git clone https://github.com/scalation/scalation_2.0.git

2. Build all the modules — change into the ScalaTion base directory and run sbt

cd scalation_2.0
sbt compile

3. Compile code or run apps — enter sbt and type compile, runMain or exit

$ sbt
sbt:scalation> compile
sbt:scalation> runMain scalation.modeling.simpleRegressionTest
sbt:scalation> runMain scalation.modeling.regressionTest
sbt:scalation> exit

The compile command is optional, since runMain compiles first if need be. A single app can also be run straight from the shell:

sbt "runMain scalation.modeling.regressionTest"

The demo and test apps are @main methods named after their class with a lower-case first letter and the suffix Test (Regression → regressionTest, regressionTest2, …).

Note: build.sbt compiles with -Werror, so any compiler warning (for example, an unused import) fails the build.

Repository layout

ScalaTion is set up to use the Simple Build Tool sbt, with the build specification build.sbt.

Path Contents
src/main/scala/scalation the source packages
docs the generated Scaladoc, published at https://scalation.github.io/scalation_2.0/
data data files for input, output and analytics (in subdirectories)
store database files
lib unmanaged jar files, if any (sbt puts every jar in lib on the classpath); see where_is_jar.txt
build.sbt, project the sbt build

To regenerate the Scaladoc in docs:

sbt clean compile doc
rm -rf docs && cp -r target/scala-3.8.3/api docs

Using ScalaTion from your own project

To develop projects that use ScalaTion but live outside ScalaTion:

1. Build the ScalaTion jar

cd scalation_2.0
sbt package          # writes target/scala-3.8.3/scalation_3-0.1.0-SNAPSHOT.jar

2. Create your project and copy the jar into its lib directory

cd your_project_dir
sbt new scala/scala3.g8          # enter a project name when prompted, e.g. hello
cd hello
mkdir lib
cp <dir>/scalation_2.0/target/scala-3.8.3/scalation_3-0.1.0-SNAPSHOT.jar lib/

where <dir> is the directory you placed scalation_2.0 in.

3. Match ScalaTion's Scala version and dependency in your build.sbt

scalaVersion := "3.8.3"
libraryDependencies += "org.scala-lang.modules" %% "scala-parallel-collections" % "1.2.0"

(An unmanaged jar does not bring its own dependencies.) Then write your code under src/main/scala and start it with sbt run.

IDE support

  • IntelliJ IDEA with the Scala plugin: open the scalation_2.0 folder and import it as an sbt project.
  • VS Code with Metals: open the folder and import the build when prompted.
